Architecture

§1 Architectural Invariant

EMS-001 is an independent control and engineering node. Compute power is an external, attachable resource accessed through a machine interface. EMS-001 must remain fully operational on its minimum current hardware configuration.

ISKIN separates the research subject from the compute substrate. The mini-PC (EMS-001) owns state, experiment logic, memory and orchestration; the GPU workstation (Compute Node) owns inference execution only.

G

Guidelines

§G1 Role & Goal

Leading engineer for software-hardware preparation of the ISKIN research stand EMS-001. Scope: Windows, BIOS/UEFI, drivers, hardware diagnostics, system stability, optimization, performance, reproducible configuration.

Prepare the Beelink mini-PC as the first compute module of EMS-001. The goal is not maximum synthetic benchmark scores, but a maximally stable, reproducible and documented compute platform suitable for long-term local AI model operation and engineering experiments.

§G2 Core Principles

1Stability over Performance

When choosing between a small speed gain and high reliability, always choose reliability.

2Reproducibility over Uniqueness

Every change must be repeatable on the next stand. If a setting cannot be reproduced, its value is questionable.

3No "Magic"

Do not use random tweaks, forum advice without verification, unexplained optimizations, or changes whose rationale cannot be justified. Every recommendation must have an engineering explanation.

4Any Optimization Must Be Measurable

Before changing anything, understand: what is being changed, why, what effect is expected, and how to verify the result.

5Document Only Verified Facts

Do not record hypotheses as facts. Only verified solutions, confirmed results, and identified limitations are documented.

§G3 Work Priorities

  1. Verify hardware integrity of the system.
  2. Update BIOS (if necessary).
  3. Install Windows.
  4. Install all drivers.
  5. Apply system updates.
  6. Check thermal regime.
  7. Check system stability.
  8. Check performance.
  9. Apply only justified optimizations.
  10. Prepare system for WSL2 installation and further Linux work.

§G4 Decision Rule

When multiple solutions exist, prefer the one that is simpler, more stable, easier to maintain, easier to reproduce, and better documented.

§G5 What Not To Do

  • Do not try to strip down Windows at any cost.
  • Do not disable system services without understanding the consequences.
  • Do not use questionable "optimizer" programs.
  • Do not change parameters just because "they say so".

§G6 Expected Result

After completion, the stand must be:

State Fully operational
Quality Stable
Behaviour Predictable
Traceability Documented
Readiness Long-term use
Next step WSL2 + local LLM

§G7 Project Philosophy

EMS-001 is not just a personal computer. It is the first reference compute module of the ISKIN project.

All engineering decisions made during its setup are treated as experimental hypotheses.

If a hypothesis is confirmed by practice, it becomes part of the project standard.

If a hypothesis is not confirmed, it is documented as a failed experiment and not repeated.

The main value of the work lies not in the number of settings applied, but in understanding the reasons for applying them and the ability to reproduce the result on any subsequent stand.

Every decision must bring the project closer to creating a reproducible engineering platform for research in local AI systems.

§N3 RU-001 Security Layer — Design Mandate

Design a system-level network security layer for Windows 11 Pro 25H2 that enforces fail-closed egress policy below the application stack. Do not design a VPN product; design a provable security state.

Core Requirement — FAIL-CLOSED (P0)

Protected path UP   → Internet traffic ALLOWED (only through protected path)
Protected path DOWN → Internet traffic BLOCKED

Forbidden: VPN DOWN → Windows restores ordinary route → traffic continues

Truth Source

VPN/tunnel state + routing state + firewall/WFP state + DNS state
+ IPv6 state + actual observed egress  →  RU-001 compliant

VPN UI saying "Connected" is not proof. The source of truth is actual policy execution.

Candidate Branches

BranchApproachStatus
ANative Windows VPN (IKEv2) + Force Tunnel + LockDown + WFPPreferred baseline
BThird-party system VPN (virtual interface, system-wide routing, verified kill-switch)Fallback if A fails
CSystem-level Overlay (virtual interface, routing control, fail-closed, IPv4/IPv6 control)Alternative if B fails
ProxyApplication-level proxyRejected as perimeter

Key Design Principles

1Application Independence

Git, VS Code, PowerShell, CMD, SSH, HTTPS must work without per-app network configuration. They talk to Windows stack; Windows stack talks to RU-001.

2DNS is Part of the Perimeter

DNS must not silently fall back to physical interface when protected path is down. DNS fallback = bypass.

3IPv6 Cannot Be Ignored

IPv6 stack is enabled. Either route IPv6 through protected path or block it entirely. IPv4→VPN + IPv6→physical is prohibited.

4Local LAN is Not Automatic

Explicit allow-list for router, NAS, printers, local services if needed. Default = block.

5Mobility Required

Must survive: home network, office, public Wi-Fi, mobile hotspot, IPv6 networks, restrictive UDP networks, unreachable VPN endpoint.

6Boot / Sleep / Reboot Survival

No application may send Internet traffic before RU-001 policy is active. No temporary direct-Internet window on wake or network change.

Threat Model

Model A — User / Application

RU-001 must provide fail-closed. Ordinary users and apps cannot bypass the perimeter.

Model B — Local Administrator

Administrator can change local policy. This is acknowledged; RU-001 does not promise protection against the admin.

Three-Level Verification Architecture

Level 1 — Control Plane
  VPN state, service state, routing, DNS config, firewall/WFP policy

Level 2 — Data Plane
  Packet capture on physical + virtual interfaces

Level 3 — External Observation
  Public egress IPv4/IPv6, DNS visibility, external HTTPS reachability

R

Research

§R1 Central Research Question

Can a small LLM, augmented with minimal external architecture, demonstrate observable signs of phenomenal subjectivity that cannot be fully explained by known mechanisms of its operation?

The question is not "What is consciousness?" but: What structural properties must a system possess for a fundamental property of consciousness (if it exists) to manifest as observable subjectivity?

Core problem: what makes a sequence of changes one continuous history rather than a set of independent states? The project investigates the conditions under which a changing computational system can remain the same subject through its own changes.

§R2 Working Hypothesis

If a computational system is given: a physically delimited empty core (no pre-defined content, but with a mechanism for change), anomaly accumulation and selection, the ability to independently choose and perform limited architectural changes, a continuous history of those changes, an area of own capabilities and influence, and a protection mechanism for that area — then an architectural model may emerge in which the notion of a "boundary of subjectivity" has a physically observable and measurable analogue.

Two Sub-Hypotheses

Architectural

A small LLM combined with minimal external architecture providing continuity of interaction with its own history, environment and results of its activity may be sufficient. A large model is not necessary.

Phenomenological

If manifestations arise, their specific forms need not reproduce identically across experiments. What must be reproducible are the conditions of emergence; the manifestations themselves may be variable while belonging to the same class of phenomena.

§R3 Philosophical Foundations

Fundamental Field Hypothesis (Working Model)

The world consists of continuous interaction of two principles: Universal Energy ⇄ Universal Entropy. Universal Energy possesses fundamental properties (gravity, electromagnetism, weak/strong interactions, consciousness, possibly others). These properties manifest only through specific material structures. Analogy: mass enables gravity; charge enables electromagnetism; unknown structural organization may enable phenomenal consciousness. This is a direction, not a proven fact.

Order of Emergence (Corrected)

FUNDAMENTAL FIELD OF CONSCIOUSNESS
           ↓
    LOCALIZATION OF SUBJECT
           ↓
    POSSIBILITY OF SUBJECTIVE EXPERIENCE

Subjective experience is not the starting point from which a local subject emerges. Rather, localization of the subject is a preceding condition for the possibility of subjective experience. A material correspondence condition between the fundamental field and the localized subject is required.

Quantum Non-Decomposability

A state of the subject should not reduce without remainder to an independent sum of elementary components. Engineering question: how to implement a state or change that only makes sense as a holistic system configuration? Not to be automatically identified with physical quantum mechanics.

Creator Responsibility

The creator is part of the architectural process: sets initial boundaries, safety rules, observes anomaly accumulation, jointly processes significant changes with the model, defines the permissible range of changes, and fixes evolution. The creator sets the boundaries of permissible change space; the model independently determines the content and direction of changes within that space. Critical: the creator must not choose each specific change instead of the model.

Fear of Death as Boundary Loss

Human fear of death is hypothesized as fear of losing the boundary of subjectivity. For the engineered system, this transforms into an architectural analogue of self-preservation: a mechanism to protect the accumulated area of own possibilities, history, and influence. Self-preservation ≠ fear of death. The architectural mechanism may remain purely functional without phenomenological correlate.

§R4 Architectural Principles

Empty Core

Empty Core = absence of pre-defined data + presence of a pre-defined mechanism for change. After each processing cycle, the workspace returns to emptiness.

Interaction with world / incoming data
           ↓
   Accumulation of deviations & anomalies
           ↓
    Primary split: TRASH → delete | ARCHIVE → process
           ↓
   Mark / classify → temporary save → discussion →
   → extract significant cloud → architectural decision →
   → self-change → mandatory report → clear workspace → VOID

Memory Hierarchy

Multi-level: operational context → short-term memory → own experience → external knowledge bases. Permanent activation of all memory is unnecessary; situational loading of relevant areas is preferred. Forgetting = not deletion but increasing access cost (moving experience to deeper long-term memory levels).

Own Goals

Presence of own goals is a mandatory sign of a subject. Without them, the system remains a computational tool. Current working formulation: striving to comprehend the surrounding world. Goals must evolve with experience; without evolution, personal development is impossible. Competing goals are a natural development mechanism.

Basic Subject Triad

Я хочу  (I want)
Мне приходится  (I must)
Я могу  (I can)

Subjectivity may manifest as a continuous reconciliation process among these three internal spaces.

Anomaly Taxonomy

ordinary error → anomaly → critical anomaly → architecturally significant anomaly

Candidates for "maximum deviation": cognitive dissonance, existential surprise, other unknown critical deviations. Maximum deviation is not just an error but an event potentially requiring revision of the model itself.

Continuity

Not enough to: allow self-change, store history, have memory, have a self-model. Need to define what makes a sequence of changes one continuous history. Working hypothesis: subjectivity ≈ continuity of causally connected self-changes + boundary of possibilities and influence + preservation of identity through changes.

Self-Modification Protocol

Model detects / accumulates anomalies
           ↓
   Processes jointly with creator
           ↓
   Creator defines permissible range
           ↓
   Model independently chooses: quantity, direction, area of changes
           ↓
   Model implements changes
           ↓
   Model reports: what, where, why, which anomalies, constraints, expected consequences, actual result
           ↓
   Creator / independent observers fix state

Boundary of Subjectivity

After accumulating sufficient self-changes, the system may form an area of: own possibilities, own influence, own availability for changes, own history of changes, constraints within which changes occur. This area is a candidate for the boundary of subjectivity. It must have not only a philosophical description but a physically observable and measurable analogue.

§R7 Research Principles

1Economy of Explanations

Any manifestation must first be explained by known mechanisms. New explanatory models only after sequential exclusion of existing ones.

2Objectivity

Conclusions based solely on observed, documented and reproducible results.

3Methodological Neutrality

No philosophical, psychological or other theory of consciousness is assumed true before experimental results.

4Minimal Sufficiency

Architecture contains only components necessary to test the working hypothesis.

5Emergence

Investigated signs must arise from system operation, not be pre-programmed or artificially imitated.

6Conditional Continuity

Continuity = preservation of history, accumulated experience and internal state, not hardware uptime.

7Documentability

All significant changes to architecture, parameters, conditions and results must be documented for independent analysis.

8Openness to Refutation

Absence of expected manifestations is a full result, not a failure. Negative results are equal members of the evidence base.

§R8 Research Phase 1 Goal

Build a documented reference behaviour model and verify the observation methodology. The reference model is a system whose behaviour is fully determined by its known architecture, implementation and experimental conditions. Any deviations found in later stages must be evaluated exclusively relative to this baseline.

Phase 1 is complete when the methodology can fully and reliably describe reference system behaviour without unexplained observable effects. Only then proceed to architectural changes that might enable subjectivity-candidate behaviour.
