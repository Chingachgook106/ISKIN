# ИТОГОВЫЙ ОТЧЁТ. Настройка EMS-001 («Малыш») по архитектуре ISKIN (ADR-001)

## 1. Исходное состояние EMS-001

- ОС: Windows 11 Pro, Version 25H2, OS Build 26200.8973.
- Аппаратная база: заводской baseline, изменений не было.
- Сеть: Ethernet, статический IP, одна подсеть с основным ПК, ping ≈ 1 мс, DNS/DoH/fallback работают.
- RDP с основного ПК: **не работает**. Предыдущий инженер настройку не завершил.
- ПО: Git отсутствует, VS Code отсутствует.
- Локальный пользователь: `indeez` (консольная сессия активна).
- Машина чистая, стендовая, предназначена только для ISKIN.

## 2. Диагностическая последовательность

1. **Служба (10.1):** `TermService` — `Running`, `StartType Manual`. Служба жива; `Manual` для неё допустим.
2. **TCP-порт (10.2):** `reg query ...RDP-Tcp /v PortNumber` → ошибка «value not found»; `netstat -ano | findstr <PID TermService>` → пусто; `qwinsta` → нет строки `rdp-tcp Listen`; `netstat -ano | findstr :3389` → пусто. **Вывод: служба запущена, но RDP-слушатель отсутствует.**
3. **Контролируемый перезапуск службы:** `sc stop TermService` → `STOP_PENDING` → возврат в `RUNNING`. Служба не останавливается при активной пользовательской сессии; переинициализация на месте невозможна, требуется перезагрузка.
4. **Параметры RDP (10.4):** `fDenyTSConnections = 0x0`; в `SystemPropertiesRemote.exe` — «разрешить подключения»; запрещающей политики в `HKLM\SOFTWARE\Policies\...\Terminal Services` не обнаружено. **Конфигурация «разрешает», но слушателя нет.**
5. **NLA (10.5):** исходно «не требуется» (галочка снята). Зафиксировано; не отключалось.
6. **WinStation RDP-Tcp:** раздел существует, но содержит только `(Default)` — конфигурация транспорта/порта отсутствует.
7. **Сравнение с эталоном:** на основном ПК тот же раздел содержит полный штатный набор значений.

## 3. Точная точка отказа RDP

Пустой раздел реестра:

```text
HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp
```

Без `PortNumber`, `fEnableWinStation` и определений транспорта (`PdDLL/PdName/WdName/...`) TermService не создаёт слушатель.

## 4. Первопричина неисправности

Конфигурация WinStation `RDP-Tcp` на EMS-001 отсутствовала/опустошена. **Почему она опустела — не установлено достоверно**; версии (действия предыдущего инженера/твикера, системный сбой) зафиксированы как гипотезы, не как факты.

## 5. Диагностические признаки, подтвердившие первопричину

- Ошибка запроса `PortNumber` при живой службе.
- `RDP-Tcp` содержит только `(Default)`.
- Эталонная машина той же семьи ОС содержит полный набор значений.
- «Разрешающие» настройки (`fDenyTSConnections=0`, UI, `Running`-служба) при отсутствующем слушателе — картина сходится только с отсутствием конфигурации WinStation.
- Финальное подтверждение: после восстановления значений и перезагрузки слушатель появился и RDP заработал.

## 6. Выполненные изменения

1. Создан и проверен файл `rdp-tcp-restore.reg` — штатные значения `RDP-Tcp` с эталонной машины (исключены пустые `REG_SZ` и не относящиеся к слушателю подразделы `TSMMRemotingAllowedApps`, `VideoRemotingWindowNames`).
2. Импорт: `reg import` `[ADMIN]` на EMS-001.
3. **Осознанное решение по безопасности:** восстановлены `UserAuthentication=1` (NLA требуется) и `SecurityLayer=2` — штатная безопасная конфигурация; клиент Windows 11 совместим. Исходное состояние NLA («не требуется») было зафиксировано до изменения.
4. Перезагрузка EMS-001 (`shutdown /r /t 0`).
5. Установлен Git for Windows (stable, опции по умолчанию).
6. Установлен VS Code (stable x64, опции по умолчанию, ярлык на рабочем столе); без расширений, без GitHub-аутентификации и синхронизации.
7. Тестовые артефакты: локальный репозиторий `iskin-test`, файл `architecture.md`.

## 7. Проверка после изменений

- `reg query`: `PortNumber = 0xd3d`, `fEnableWinStation = 0x1`.
- После загрузки: `qwinsta` → `rdp-tcp ... Listen`; `netstat -ano | findstr :3389` → `LISTENING`.
- Первый клиентский запуск: ошибка `0x104` из-за ввода имени пользователя вместо адреса (клиентская ошибка, не системная); после указания статического IP — подключение успешно.
- Предупреждение о сертификате при первом подключении — самоподписанный RDP-сертификат, штатное поведение; принято. Вход с NLA успешен.

## 8. Проверка устойчивости после перезагрузки

- Перезагрузка выполнена как часть применения изменения; после неё слушатель и подключение работают.
- Циклы «выход из сеанса → повторное подключение» и «локальный вход → перехват сессии» проверены: возобновление отключённой сессии и корректная передача единственной сессии работают воспроизводимо.

## 9. Итоговая конфигурация RDP

- Порт 3389; `fEnableWinStation=1`; транспорт `tcp/tdtcp`; `SecurityLayer=2`; `UserAuthentication=1` (NLA); `MinEncryptionLevel=2`; `fDenyTSConnections=0`.
- Windows Firewall **включён**; правила пропускают RDP (доказано успешным подключением при включённом Firewall).
- Роль RDP — административный канал (пункт 8 ТЗ); экспериментальный контур от него не зависит.

## 10. Состояние Git

- `git version 2.55.0.windows.3`; доступен из терминала.
- Локальный репозиторий инициализируется и работает (`iskin-test`, ветка `master`, без коммитов).
- Ключи, удалённые репозитории, GitHub-аутентификация не настраивались (пункт 14 ТЗ).

## 11. Состояние VS Code

- Stable x64; `code --version` работает (версия и commit-хеш присутствуют, архитектура x64); запуск из меню и с ярлыка.
- Редактирование и сохранение локальных файлов проверено (`architecture.md`, контрольное чтение в Notepad).
- Расширения не установлены; Compute Node не требуется (пункты 13, 15 ТЗ).

## 12. Выявленные особенности Windows 11 25H2 (имеющие значение)

- `TermService` не останавливается при активной пользовательской сессии (`STOP_PENDING` → `RUNNING`): переинициализация RDP-конфигурации возможна только перезагрузкой.
- Клиентская SKU: одна интерактивная сессия — локальный вход отключает RDP и наоборот. Это штатное поведение, не дефект.
- Самоподписанный RDP-сертификат: предупреждение клиента при первом подключении — ожидаемо.
- Односторонний буфер обмена RDP (основной ПК → EMS-001 работает, обратно — нет). Зафиксировано как особенность; не расследовалось за отсутствием диагностической необходимости.

## 13. Что не потребовало изменения

- Сетевая конфигурация (статический IP, DNS, DoH, fallback).
- Windows Firewall (ни разу не отключался; правила не правились).
- Локальные политики безопасности (запрещающих не обнаружено).
- Аппаратная конфигурация и RAM (пункты 4, 5, 19 ТЗ).
- Серверные компоненты, оркестрация, Docker, GPU-протоколы (пункт 16 ТЗ) — не устанавливались.

## 14. Что сознательно оставлено для следующих этапов ISKIN

- Машинные интерфейсы EMS-001 ↔ Compute Node (SSH/API, jobs) — пункт 17.
- Настройка Compute Node — пункт 16.
- GitHub-аутентификация, ключи, удалённые репозитории — до реальной потребности.
- Расширения VS Code — только по необходимости.
- Локальная git-идентичность (`user.name`/`user.email`) и, при желании, `init.defaultBranch=main` — перед первыми реальными коммитами.
- Расследование одностороннего буфера RDP — если начнёт мешать.

## 15. Рекомендации по документированию (GitHub / инженерная документация ISKIN)

1. Создать на EMS-001 локальный репозиторий `iskin-docs` и положить в него: ADR-001, данное ТЗ, этот отчёт, `rdp-tcp-restore.reg` (перенести с рабочего стола), README базовой конфигурации EMS-001 (роль, IP, учётка, способ подключения, порядок восстановления `RDP-Tcp`).
2. Оформить инцидент «пустой RDP-Tcp» как incident report с диагностической последовательностью из раздела 2.
3. Ремотов не заводить до отдельного инженерного решения; документация живёт локально и версионируется Git.
4. Любые будущие изменения базовой конфигурации оформлять по правилу «почему / что / зачем / проверка».
