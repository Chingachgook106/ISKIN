# Экспертное ТЗ: минимальный автономный software stack «Малыша» для проекта ISKIN

## 1. Контекст проекта

Мы проектируем локальную экспериментальную AI-систему **ISKIN**.

На текущем этапе задача не состоит в обучении большой LLM с нуля. Нам необходимо подготовить физическую Windows-машину **«Малыш»** к последующей автономной разработке, запуску и исследованию локальной языковой модели.

В качестве семейства базовой модели предварительно рассматриваются:

* **OLMo**
* **LLM360**

Конкретная модель пока не выбрана.

Ключевой архитектурный принцип:

> **До программной изоляции машины необходимо установить весь минимально необходимый software stack. После Isolation машина должна быть способна продолжать разработку и исследование без ослабления perimeter только ради установки недостающего ПО.**

Уже установлено:

* Chrome;
* Firefox;
* Git;
* GitHub CLI.

Git и GitHub CLI установлены **без регистрации и авторизации**.

Также действует принцип:

> **Не устанавливать программные компоненты «на всякий случай».**

Каждый компонент должен иметь конкретное обоснование с точки зрения дальнейшей автономной работы.

## 2. Ограничения оборудования

Используй следующие характеристики машины:

**CPU:** Модель	AMD Ryzen 7 5800H, Ядер / потоков - 8C / 16T, Частота в BIOS ~3239 MHz.

**GPU:** AMD Radeon Graphics (Vega, 8 CUs, до ~2000 MHz), интегрированная в APU Ryzen 7 5800H.

**VRAM:** выделенной VRAM нет; iGPU использует системную оперативную память (shared memory). Объём, доступный под графику, зависит от настроек BIOS/UEFI и текущей нагрузки; физически это часть установленных модулей DDR4.

**RAM:** Установлено 2×8 GB DDR4, режим Dual‑Channel, частота ~2933 MHz.

**Storage:** Micron 2400 MTFDKBA512QFM, 512 GB, NVMe PCIe (M.2 2280).

**OS / версия Windows:** Microsoft Windows 11 Pro (Build 26200 / 25H2).

**Архитектура ОС:** System Type: x64-based PC.

**Дополнительные ограничения:** 
 - отсутствие глобального IPv6 (только IPv4, как в базовом снимке сети);
 - отсутствие выделенного NPU/TPU (только CPU + iGPU);
 - работа в среде с DPI/ТСПУ (РФ, Roskomnadzor), что влияет на выбор сетевых решений.

Если каких-либо данных недостаточно для окончательного выбора, явно укажи, какие именно данные критичны.

## 3. Что требуется определить

Проведи инженерный анализ минимального software stack, который следует установить **ДО Isolation**.

Особенно необходимо определить:

### A. VS Code Extensions

Определи **минимально необходимый** набор расширений VS Code.

Для каждого расширения укажи:

* название;
* назначение;
* почему оно необходимо именно для нашего проекта;
* является ли оно обязательным или только рекомендуемым;
* может ли его функция быть выполнена встроенными средствами VS Code.

Отдельно перечисли расширения, которые **не следует устанавливать** на Baseline, несмотря на их популярность или удобство.

Особое внимание:

* Git / GitHub;
* Python;
* Jupyter;
* debugging;
* Markdown;
* JSON/YAML;
* JavaScript/TypeScript — только если реально необходимы;
* AI assistants / Copilot-подобные расширения;
* remote development;
* Docker;
* Hugging Face;
* ML/LLM-specific extensions.

Не включай extension только потому, что он «полезный» или «популярный».

---

### B. Python stack

Определи минимальный Python stack для предполагаемого сценария:

> локальный запуск → исследование → модификация кода → эксперименты с моделью.

Определи:

* версию Python;
* способ установки Python;

* `venv`, `conda`, `uv` или другой механизм — выбрать один основной вариант;

* обязательные базовые пакеты;
* необходимость Jupyter;
* необходимость дополнительных инструментов разработки.

Особенно важно определить, что действительно необходимо для OLMo / LLM360, а что является избыточным.

### C. PyTorch

Не предлагай полный стандартный ML-stack автоматически. Рассматривай только реально необходимые компоненты.

### D. Hugging Face ecosystem

Определи минимальный набор Hugging Face компонентов, если они необходимы.

Отдельно рассмотри:

* `transformers`;

### E. Launcher / runtime

Определи, каким способом рациональнее всего запускать выбранный класс локальной модели на данной машине.

Рассмотри, если применимо:

* native Python / PyTorch;
* Hugging Face Transformers;
* llama.cpp;
* vLLM;
* Ollama;
* другие специализированные runtime.

Но не составляй каталог всех существующих решений.

Нужно выбрать:

**PRIMARY → FALLBACK → НЕ НУЖНО**

с кратким техническим обоснованием.

Учитывай, что наша цель — не просто inference, а последующее **исследование и возможная модификация модели**.

Определи:

Особенно важно избежать установки лишнего software stack.

---

### G. Node.js

Определи, нужен ли Node.js вообще.

Не исходи из того, что VS Code или современная разработка автоматически требуют Node.js.

Рассмотри только потребности нашего проекта.

Если Node.js необходим:

* рекомендуемая версия;
* npm / corepack / другой package manager;
* обязательные пакеты.

Если не необходим — так и напиши.

---

### H. Docker

Определи, нужен ли Docker на Baseline.

Учитывай:

* ограничения оборудования;
* автономность после Isolation;
* необходимость работы с локальной моделью;
* дополнительную поверхность атаки;
* дополнительные системные компоненты;
* потенциальную сложность восстановления/обслуживания после Isolation.

Если Docker не нужен на первом этапе — **не включай его в Baseline**.

## 4. Критерии принятия решения

Для каждого компонента используй следующий принцип:

### MUST

Без него после Isolation существует реальный риск невозможности продолжить основной сценарий работы.

### SHOULD

Он существенно облегчает работу, но отсутствие не блокирует основной сценарий.

### OPTIONAL

Удобен, но для Baseline не нужен.

### REJECT

На текущем этапе устанавливать не следует.

---

## 5. Дополнительное требование: автономность

Проверь все выбранные компоненты с точки зрения сценария:

> **Internet доступен только на этапе подготовки → Baseline Freeze → Isolation → Internet/perimeter больше не используется для установки недостающего software.**

Поэтому отдельно выяви:

* компоненты, которым требуется online activation;
* компоненты, которым требуется аккаунт;
* компоненты, требующие cloud synchronization;
* компоненты, которые после установки могут работать полностью offline;
* компоненты, которые при первом запуске могут пытаться обращаться во внешний интернет.

**Регистрация, авторизация и cloud sync не должны попадать в Baseline автоматически.**

# 6. Требуемый результат

Не пиши длинный обзор рынка.

Нам нужна **инженерная рекомендация для принятия решения**.

Ответ должен завершаться ровно тремя разделами.

## ВЫВОД 1 — BASELINE

Максимально конкретный список того, что **НЕОБХОДИМО установить до Isolation**.

Формат:

| Компонент | Версия | MUST/SHOULD | Причина |
| --------- | ------ | ----------- | ------- |

Включай только реально необходимые компоненты.

---

## ВЫВОД 2 — VS CODE EXTENSIONS

Отдельный минимальный список VS Code Extensions.

Формат:

| Extension | MUST/SHOULD | Назначение |
| --------- | ----------- | ---------- |

В конце одной строкой:

**Extensions, которые НЕ устанавливаем: …**

---

## ВЫВОД 3 — FREEZE / ISOLATION CHECK

Короткий checklist того, что должно быть проверено непосредственно перед Freeze.

Максимум **15 пунктов**.

Формат:

* [ ] …
* [ ] …
* [ ] …

Последний пункт должен отвечать на вопрос:

> **Можно ли после Isolation продолжить разработку, запуск и исследование локальной модели без установки дополнительного ПО через внешний perimeter?**

---

## 7. Жёсткие ограничения на ответ

1. Не писать общую лекцию о LLM.
2. Не объяснять историю OLMo, LLM360, PyTorch и VS Code.
3. Не предлагать популярные инструменты «на всякий случай».
4. Не смешивать MUST и OPTIONAL.
5. Не рекомендовать cloud services без отдельного обоснования.
6. Не предполагать наличие не указанного оборудования.
7. Если решение зависит от неизвестной характеристики железа — явно указать зависимость.
8. Если есть два разумных варианта — выбрать **один PRIMARY** и один FALLBACK.
9. Все версии, которые могут существенно измениться, должны быть указаны с датой актуальности.
10. Финальные три раздела (**ВЫВОД 1 / ВЫВОД 2 / ВЫВОД 3**) должны быть **тезисными и максимально компактными**.

**Главная задача эксперта: не перечислить максимум доступных инструментов, а определить минимальный набор, после установки которого «Малыш» можно безопасно перевести в состояние Freeze → Isolation без потери возможности продолжать работу над ISKIN.**
