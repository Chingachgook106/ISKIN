# РЕЗОЛЮЦИЯ Perplexity


Ниже — мой инженерный вариант решения: не «полный ML-стек», а минимальный замороженный набор для Windows-машины с 16 ГБ RAM, интегрированной Vega-графикой и без NVIDIA CUDA. Основной вывод: **ставить CPU-ориентированный Python/PyTorch-стек, а AMD/iGPU рассматривать только как экспериментальный DirectML fallback**.

## Ключевая позиция

На такой конфигурации реалистичны:

- запуск небольших моделей и отдельных исследовательских экспериментов;
- анализ кода, токенизаторов, датасетов и checkpoint-файлов;
- inference небольших моделей в CPU-режиме;
- ограниченные эксперименты с LoRA/модификацией кода.

Нереалистичны:

- полноценное обучение 7B+ модели;
- комфортный запуск 7B-модели в обычном FP16;
- использование vLLM;
- CUDA-стек;
- Docker/WSL как обязательная основа;
- полагание на интегрированную Vega как на полноценный ML-ускоритель.

Для OLMo минимально разумная точка входа — небольшая модель вроде OLMo 1B/2 1B. Для LLM360 следует сначала проверить конкретный репозиторий и формат checkpoint: семейство неоднородно, поэтому нельзя заранее обещать совместимость одного универсального launcher’а.

PyTorch нужен: официальная Windows-установка допускает CPU-вариант, а DirectML существует как отдельный пакет `torch-directml`; однако DirectML следует считать экспериментальным путем, а не базовой платформой.  Поддержка AMD-ускорения PyTorch от AMD ориентирована на существенно более новые Radeon/Ryzen AI-продукты, а не на Vega 8 Ryzen 7 5800H.[^1][^2][^3][^4]

## Архитектура baseline

### Python

**PRIMARY:** CPython 3.11 x64 + встроенный `venv` + `pip`.

Причины:

- Python 3.11 достаточно зрелый для Windows и современного Hugging Face-стека;
- `venv` не добавляет отдельный runtime и не требует Conda;
- после Freeze окружение легко архивировать или восстановить локально;
- `pip freeze` позволяет получить точный inventory;
- Conda на данной машине добавит заметный объём и отдельную систему разрешения зависимостей.

`uv` технически привлекателен, но для baseline его не требуется: он является дополнительным инструментом, а не необходимым условием работы. Его можно рассмотреть позднее, если появятся проблемы с воспроизводимостью или скоростью установки.

Рекомендованная структура:

```text
D:\ISKIN\
├── env\
├── src\
├── scripts\
├── notebooks\
├── models\
├── datasets\
├── wheels\
└── requirements-lock.txt
```

Создание окружения:

```powershell
py -3.11 -m venv D:\ISKIN\env
D:\ISKIN\env\Scripts\Activate.ps1

python -m pip install --upgrade pip setuptools wheel
```

После установки:

```powershell
python -m pip freeze > D:\ISKIN\requirements-lock.txt
```


### PyTorch

**PRIMARY:** CPU build PyTorch.

Не устанавливать:

- CUDA Toolkit;
- NVIDIA driver;
- cuDNN;
- `torchvision`;
- `torchaudio`;
- полный ROCm;
- сторонние AMD ML-пакеты без подтвержденной совместимости с Vega 8 и Windows.

Минимальная установка:

```powershell
python -m pip install torch
```

Версию лучше зафиксировать на реально проверенной стабильной версии, а не указывать «последнюю» без даты. На дату подготовки рекомендации — **23 августа 2026 года** — точную версию следует получить с официальной страницы PyTorch непосредственно перед загрузкой wheel-файлов, затем зафиксировать её в lock-файле.

Практическое правило:

```powershell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
```

Ожидаемый результат для baseline: `torch.cuda.is_available()` возвращает `False`. Это нормально: CUDA на данной машине отсутствует.

### DirectML

DirectML — **SHOULD/FALLBACK**, не MUST.

Установка имеет смысл только после проверки CPU-сценария:

```powershell
python -m pip install torch-directml
```

Microsoft указывает `torch-directml` как способ запуска PyTorch inference на совместимом Windows-оборудовании, включая DirectX 12 GPU.  Но на Vega 8 возможны:[^1]

- отсутствие полезного ускорения;
- несовместимость отдельных операций;
- проблемы с генерацией;
- перенос части операций обратно на CPU;
- более низкая стабильность по сравнению с CPU.

Поэтому DirectML не должен быть единственной рабочей опорой после Isolation. Если его устанавливать, необходимо заранее сохранить отдельный smoke test и не смешивать DirectML-зависимости с критически важным CPU-окружением без проверки.

### Hugging Face

Минимальный стек:


| Компонент | Статус | Обоснование |
| :-- | --: | :-- |
| `transformers` | MUST | Основной интерфейс к OLMo и совместимым моделям |
| `huggingface_hub` | MUST | Загрузка и локальное управление моделями/checkpoint’ами |
| `safetensors` | MUST | Безопасный и распространённый формат весов |
| `tokenizers` | MUST/транзитивно | Нужен для токенизации; часто подтягивается через `transformers` |
| `accelerate` | SHOULD | Полезен для device mapping, загрузки и исследовательских сценариев |
| `datasets` | SHOULD | Нужен только если планируются локальные эксперименты с датасетами |
| `evaluate` | REJECT на baseline | Не нужен для запуска и базового исследования |
| `peft` | SHOULD при LoRA | Устанавливать только если LoRA/адаптеры входят в ближайший план |
| `trl` | REJECT | Не нужен для минимального запуска |
| `bitsandbytes` | REJECT | Не является надежной базовой ставкой для этой Windows/AMD-конфигурации |
| `deepspeed` | REJECT | Избыточен и практически бесполезен на данной машине |

Установка минимального варианта:

```powershell
python -m pip install "transformers>=4.48" huggingface_hub safetensors accelerate
```

Для актуальных OLMo 2 на Hugging Face указывается совместимость с `transformers` версии 4.48 и выше.  Для некоторых ранних вариантов OLMo 2 требовалась установка `transformers` непосредственно из GitHub до выхода соответствующей версии в PyPI; это ещё одна причина фиксировать конкретный checkpoint и протестированный набор версий, а не устанавливать всё «на будущее».[^5][^6][^7][^8]

`datasets`:

```powershell
python -m pip install datasets
```

Устанавливать его до Isolation стоит только при наличии хотя бы одного локального исследовательского сценария: загрузка, фильтрация, преобразование или сохранение датасетов. Для простого запуска готовой модели он не нужен.

### Jupyter

Jupyter — **SHOULD**, если исследование действительно предполагает notebook workflow.

Минимум:

```powershell
python -m pip install jupyterlab ipykernel
python -m ipykernel install --user --name iskin --display-name "ISKIN Python 3.11"
```

Если работа ведётся только через `.py`-скрипты, Jupyter можно не ставить. Но для исследовательского проекта его разумно включить: он полезен для анализа токенизации, параметров, активаций, памяти и результатов экспериментов.

`jupyterlab` не требуется устанавливать как отдельное серверное окружение вне Python virtual environment.

## Launcher и runtime

| Роль | Выбор | Решение |
| :-- | :-- | :-- |
| PRIMARY | Native Python + PyTorch + Transformers | Лучший вариант для исследования и модификации |
| FALLBACK | `llama.cpp` через заранее проверенный portable build | Только для GGUF-моделей и быстрого CPU inference |
| НЕ НУЖНО | vLLM | Требует GPU-ориентированной инфраструктуры и не соответствует машине |
| НЕ НУЖНО | Ollama | Удобен для потребления моделей, но скрывает детали, мешает исследовательскому сценарию и добавляет отдельный runtime |
| НЕ НУЖНО | Docker | Не нужен для первого этапа |
| НЕ НУЖНО | CUDA/ROCm stack | Нет соответствующего оборудования и практической потребности |

`llama.cpp` не следует включать в Python baseline автоматически. Его стоит добавить только если выбранная модель уже доступна в GGUF и важен быстрый локальный inference. Для исследования исходной архитектуры, загрузки checkpoint’ов и изменения кода PRIMARY остаётся Transformers.

Критическое ограничение: `llama.cpp` не является универсальным launcher’ом для любого OLMo или LLM360 checkpoint. Он зависит от поддерживаемой архитектуры и формата модели.

## Автономность и сеть

До Freeze нужно не просто установить пакеты, а подготовить локальный запас материалов:

- Python installer;
- wheels всех пакетов и зависимостей;
- установщик VS Code;
- VSIX выбранных расширений;
- локальный кэш Hugging Face;
- tokenizer;
- checkpoint выбранной модели;
- документацию и README;
- smoke-test scripts;
- зафиксированные хэши файлов;
- lock-файл окружения.

Hugging Face Hub не требует постоянного cloud-доступа после того, как модель и tokenizer полностью скачаны. Но первый запуск может обращаться к Hub, проверять файлы, пытаться обновить metadata или искать отсутствующие компоненты. Поэтому до Isolation нужно проверить offline-режим:

```powershell
$env:HF_HUB_OFFLINE="1"
$env:TRANSFORMERS_OFFLINE="1"
```

Затем выполнить отдельный запуск без сетевого доступа. Нельзя считать модель автономной, пока не проверены:

- все shards;
- tokenizer files;
- config;
- generation config;
- custom code, если он используется;
- зависимости конкретного репозитория;
- локальные пути в конфигурации.

Git и GitHub CLI не требуют авторизации для локальной работы с уже имеющимся репозиторием. Однако private repositories, GitHub API, LFS-загрузка и remote operations после Isolation будут недоступны без заранее подготовленных credentials или локальной копии. Авторизацию не следует выполнять автоматически: это отдельное решение безопасности.
